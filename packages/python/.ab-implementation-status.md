### Phase 2 — Completed 2026-08-16
- Added `_run_pharos_cli(*args) -> str` helper after `_get_pharos_cli()` (line ~840).
  Uses `asyncio.create_subprocess_exec` with 30s timeout. Returns JSON with
  `status` (ok/error), `stdout`, `stderr`, `returncode`. On timeout: includes
  `"timeout": True` flag. On FileNotFoundError: includes `"hint"` key.
- `pharos_info` and `pharos_publish` added inside the `if not MCP_APPS_MODE:` block
  (CLI-mode only). `pharos_publish` takes optional `server_card_path` — when empty,
  runs `pharos publish` without a directory argument.
- 22 non-A/B tools added after `pharos_daemon_status`, before MCP Resources section.
  All registered unconditionally (available in both CLI and Apps modes).
- `pharos_config` has special logic: when `value` is empty, runs `pharos config <key>`
  (get mode); when value is provided, runs `pharos config <key> <value>` (set mode).
- Skipped interactive CLI commands: `login` (browser OAuth), `init` (scaffolding),
  `package` (sub-command of publish), `republish` (rarely needed).
- All 89 tests pass: `python -m pytest tests/unit/test_mcp_server.py -v`

### Phase 3 — Completed 2026-08-16
- 6 HTML template constants added after `OAUTH_HTML` (line ~783), each a full
  `<!DOCTYPE html>` document with inline CSS and JS (no external resources).
- Shared CSS base `_APPS_BASE_CSS` provides GitHub dark theme variables:
  `--bg: #0d1117`, `--accent: #58a6ff`, IBM Plex Sans/Mono font stacks,
  monospace class for data fields, badge/button/status component styles.
- Anti-AI-slop design: no purple gradients, no glassmorphism, no emoji headers,
  no border-left accent cards, tables for list data, monospace for IDs/versions,
  clear type hierarchy (18px title / 14px section / 13px body / 11px labels).
- `pharos_search_apps` returns JSON `{status, results, count, search_id, html}`
  with a results `<table>` (name, transport, tools, publisher, Install button).
- `pharos_info_apps` returns JSON `{status, server_id, server, html}` with a
  detail card (name, description, version, publisher, transport, endpoint,
  tools, pricing, capabilities, tags, Install button).
- `pharos_install_apps` calls `_create_pending_connection()`, returns
  `{status: "pending_approval", approval_token, server_id, message, html}`.
  The `approval_nonce` is in the HTML data only (not a top-level JSON key).
  Approve button does `fetch("/approve", {approval_token, approval_nonce})`.
- `pharos_remove_apps` creates a `rm-` prefixed token with UUID4 nonce,
  returns `{status: "pending_removal", removal_token, server_id, message, html}`.
  Remove button does `fetch("/approve", {approval_token: removal_token, approval_nonce})`.
- `pharos_list_apps` reuses list logic (in-memory + CLI `list --json`),
  returns `{status, servers, count, html}` with an installed-servers `<table>`.
- `pharos_publish_apps` reads server card JSON from `server_card_path`,
  creates a `pb-` prefixed token with UUID4 nonce, returns
  `{status: "pending_publish", publish_token, server_id, message, html}`.
  Publish button does `fetch("/approve", {approval_token: publish_token, approval_nonce})`.
- Security: all JSON→HTML injections use `.replace("<", "\\u003c").replace(">", "\\u003e")`;
  all user data rendered via `textContent` / DOM APIs (no innerHTML with user data);
  all event handlers via `addEventListener` (no inline onclick); nonce never appears
  as a top-level JSON key in the AI-visible response.
- 7 new tests in `TestAppsModeTools` class use `importlib.reload` with
  `PHAROS_MCP_APPS=true` to test apps-mode functions in isolation, then
  restore CLI-mode module for subsequent tests.
- All 96 tests pass (89 pre-existing + 7 new): `python -m pytest tests/unit/test_mcp_server.py -v`
